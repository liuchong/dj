# 退订、出站过滤与单条强制发送

DJ 使用本地 SQLite 保存收件人的选择和出站台账。退订由服务根据真实入站消息识别、保存并执行，AI不负责核实、登记或解除，也不能用自己的任务备注代替服务状态。

## 两种过滤，方向不同

| 设置 | 阻止什么 | 仍然允许什么 |
| --- | --- | --- |
| 订阅条件、人员/字符触发黑名单 | 消息自动通知AI | 接收、记录、历史和上下文读取 |
| 收件人退订、出站黑白名单 | 向目标发送文字、编辑或新增表情（含Working/Get） | 来信、事件及原订阅正常触发；撤回和清理已有受托表情 |

消息被送到AI，不代表可以向其发送者回复；有平台发送权限也不等于收件人同意。

## 收件人如何退订和恢复

人类在已接入的群或私聊发送独立的 `TD`（大小写不敏感）或 `退订`，DJ按原生发送者登记禁收；群里不要求引用DJ消息。正文包含这些词、机器人消息及已知自身回声不算命令。服务启动时也会分页恢复本地已收到但漏登记的命令，保留源时间较新的选择。

禁收后不向对方自动发送确认，也不新增Working/Get等表情；原有受托表情继续清理。对方主动发送独立的 `恢复接收` 才解除。普通问候、重新提问或再次@都不会解除，重启后也不会丢失。

群内禁收针对明确回复或原生@该人；普通群广播无法只对某个成员隐藏。不能把一个人的退订扩大成全群禁发。同一可证原生身份命名空间内的连接共享选择，不按姓名猜测不同应用或平台的身份。

## AI收到禁收错误

`recipient_opted_out` 表示收件人退订，`recipient_blocked` 表示出站策略拦截。默认停止发送，不换账号、CLI或其他渠道绕过。已排队内容在真正提交前也会复查；`outbound.get` 可以查看 `blocked_reason`、`definite_not_sent` 和 `retryable`。

管理员可通过 `message.recipient_policy.get` 读取服务保存的选择，并用 `message.recipient_policy.set` 管理出站黑白名单；白名单不解除退订。管理操作需要独立权限，普通AI不需要取得该权限才能让禁收生效。

## 用户明确要求强制发送一次

只有用户明确要求“本次强制发一次”等豁免指令时，AI才可以在 `message.send` 或 `message.reply` 中传布尔参数 `force_send: true`；默认false。普通“回复一下”、任务紧急或AI认为有必要，都不能自行启用。不要保存为长期默认值。

```json
{"reply_context_id":"reply_context_example","content":{"type":"text","text":"用户明确要求的本次回复"},"force_send":true,"idempotency_key":"explicit-send-once"}
```

主动发送时用 `destination_ref` 替代 `reply_context_id`。此参数只豁免这一出站记录的退订及出站黑白名单，保存在台账并由 `outbound.get` 返回。它不恢复接收、不放开后续消息、编辑或自动表情；固定身份和位置、平台权限、正文大小以及防重校验照常执行。

重用原幂等键核对结果；`unknown` 先查询和核实，不换键重发。服务能限制参数的类型与作用域，不能从一个布尔值证明用户确实授权；调用方必须遵守明确授权要求。
