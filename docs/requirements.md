## 从业务必然推导的约束

这些是实现 Q02–Q07 所需的工程条件，不冒充用户额外提出的功能。

- E01：稳定目标身份与临时进程/端口分开。标题只是展示，历史记录不证明可收件。
- E02：常驻收件、规则处理和持久化属于 DJ，订阅生命周期不依赖一次 MCP 调用或 Agent 当前回合。
- E03：区分事件收到、接口接受、开始处理、回合结束、业务完成；不把发送成功写成完成任务。
- E04：同一来源事件去重；发送结果不明时先核对，不能盲目重发。
- E05：订阅只能使用已授权来源与目标，保留发送者、账号和话题边界。
- E06：有界队列、积压可见、恢复可解释；源平台无法重放时公开缺口。
- E07：保留事件版本、触发原因与明确回复目标，控制自身回复形成的消息循环。

## 当前设计选择

- 单机常驻服务配可复用核心，多个调用入口共享业务层与状态。采用 Eliscript → ESM/Bun、SQLite 和本地 UDS，选型见 technical-stack.md。
- Lark / 飞书官方实时接口，user/bot 统一路由；AI 使用已有实例的跨进程接收端。具体工具与其他 IM 的验证边界见[能力范围](release-scope.md)和[状态](status.md)。
- 规则只使用确定性的来源、发送者、提及、回复、正文和事件类型匹配；理解自然语言、生成规则属于调用方模型，DJ 仅验证和执行。
- 忙碌目标默认由 DJ 排队；主动中途追加属于显式策略并要求适配器支持。
- 先支持文本事件；附件以受控元数据和访问引用表达，具体媒体能力逐适配器声明。
- 统一入口包含对话发现、消息列举/读取/搜索、发送/回复、订阅与投递诊断。平台不具备能力时返回明确不支持。
- 一个 Agent 会话可关联多个订阅。每个订阅有一个目标，多个目标用多条订阅表达，便于独立撤销与授权。
- 会话查询、定向输入和显式生命周期操作独立于订阅；工具类型、运行实例、原生会话与已登记 AgentTarget 分开。追加能力以 agent-control-plane.md 为准。

## 后续扩展候选

更多媒体格式和图形管理界面是后续候选，不能默认扩大当前范围。DJ 自身的语义分类、自动摘要、模型推理与完整任务调度不属于产品边界；调用方可自行使用 AI，并通过相同显式接口提交结果。

不承诺任意现有 TUI 自动接管、所有客户端共享实时上下文、所有聊天内容均可访问、所有平台全量历史重放或业务效果恰好执行一次。

## 面向模型的责任分配

调用方模型负责把用户意图映射为明确来源、目标和结构化规则。DJ 不推断意图；以服务返回的 conversation_ref/candidate_ref、不可变 preview_id 和幂等操作记录减少拼参错误，并在运行时独立校验。参数合法不证明语义符合用户意图，该限制必须公开。性能基线与路由预算见 [组件契约](component-contract.md)，调用闭环见 [模型接口](model-facing.md)。
