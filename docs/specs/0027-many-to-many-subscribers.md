# 多对多主动订阅与同事件订阅者提示

## 职责

DJ 是消息分发枢纽。一个调用身份可以登记多个准确原生对话；每个对话可以创建多个订阅，同一事件可交给多个对话和不同 AI 工具。退订只影响该订阅，既不保留独占权，也不自动把消息迁移给别的对话。协作、任务归属、是否重复处理由 AI 和用户决定。

## 接入

部署时为本机 AI 配置普通 `local-ai` 主体及私有客户端 profile，默认 `~/.dj/client.json`；管理凭据单独保存，不交给模型。共享身份代表获准本机调用方，不代表当前对话。AI 自行 discover、核对准确 native_session_id/实例/工作区，register 后使用显式 agent_id 建立订阅，无需每个对话再次找操作员发凭据。可选 target_constraint 只收窄授权范围；省略不代表禁止登记。平台凭据、原生进程归属、实例 epoch、类型化引用和 action grants 继续检查。

`agent.whoami` 返回 `bound_agent_ids` 数组，不任意选一个对话作为“自己”。原生目标仅保留一条登记，重复登记返回原记录；不同主体不可抢占他人的登记。需要安全隔离的部署仍可配置受限独立主体，普通本机对话无需逐个配置。显式固定接线按 recipient 与准确 native target 查找，不能只按 recipient 选第一条。

OpenCode endpoint 指向经过进程归属验证的本机服务实例；已有对话在该实例内按原生 ID 发现，不局限于 endpoint 的创建目录。project_id、directory 随会话元信息返回；创建新对话仍使用明确配置的工作区。

## 提示

服务配置 `subscriber_hints` 缺省为 true；false 完全关闭。push 和 pull 信封都可带 `subscriber_hints`：basis=same_event、subscribers、has_more、instruction。仅列同一 event_id 已实际匹配、当前仍有效的其他已登记接收对话，并按当前权限过滤；每个接收对话只列一次，最多 32 个，超出明确 has_more。标题、工具、准确原生 ID、工作区和已知模型仅供协作参考，不猜同任务、父子关系或负责人。

提示不引入排队、互斥、转交、抢占或单消费者限制；同一目标的多个订阅仍按已有投递归并机制合并。同事件提示是生成信封时的快照，不保证后续订阅状态不变化。

## 验收

真实 SQLite 上同主体登记两个目标并同时订阅同一事件，两边均获得通知；退订一边不影响另一边。whoami 返回所有登记；固定接线不误选其他目标；约束和跨主体抢占继续拒绝。push/pull 正确列实际同事件接收者、去重、关闭开关和权限过滤。现有对话规则、消息历史和收件人退订状态不因接线更新而重写。
