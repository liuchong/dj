# 0005 — 原生提及与确定性回复路径

## 职责

DJ根据平台原生提及及已保存的身份映射固定回复账号和原消息位置。AI可以看到被提及者和选定身份，但不选择回复账号、收件人或会话。AI只按自己维护的业务规则判断是否、何时调用`message.reply`并提交内容及受保护的`reply_context_id`。该操作不接受身份或目的地覆盖参数。

触发通知不等于新任务；多个通知可以归属同一任务，也可无需处理。AI普通输出、最终回答和任务完成均不自动转发IM，不能接管stdout或结束回调来冒充回复。真正外发仅由显式回复工具调用产生，允许在最终回答前执行。

## 数据和设置

平台原生`mentions`在接收、持久化、消息查询及push/pull信封中保留。`mentions.id`支持`eq`/`in`成员匹配：显式空列表不命中，缺失元数据为indeterminate；正文中的`@名字`不算提及。不按sender是否本人过滤，手工自发@本人或@bot同样处理。DJ已确认的外发回声去重与服务级黑名单继续有效。

接收AI自行通过`session.rules.update`维护本对话的`reply_routes`，并读回验证。每项只有`source_connection_id / mention_id / reply_connection_id`，最多32项；mention_id仅在指定源连接的当前身份版本内有效，不能跨应用复用OpenID。DJ保存源及出口的identity_revision。不同IM网络、明确冲突的租户或重复歧义映射拒绝，不增加跨账号自动故障切换。省略字段保留原设置，`[]`显式清空。该设置仅定义稳定身份映射，不把逐消息回复决策交给AI。

## 固定、校验与失败

- 冻结通知或领取时，DJ按原生mentions、连接已登记自身ID和同一原生消息的确定证据选择出口。存在无法解析的提及时返回unmapped_target，不以收件连接代替被询问身份；没有提及或确定回应目标的关键词通知才适用来源默认。
- 同一消息命中多个不同出口时公开`reply_route.status=ambiguous_target`，不生成可发送的reply_context、不自动双发、不让AI选择身份。匹配映射身份版本过期则为stale_reference，绝不回退其他账号。
- 单一出口生成的reply_context固定原chat/thread/message及出口connection和identity_revision；另存原来源地址及版本。出口只能是同平台、品牌且无明确租户冲突的获准连接，跨连接当前仅支持Lark。缺失租户标识不作为同租户证明；真正发送固定使用原生message_id的回复接口，由平台复核该出口访问原消息的权限，绝不改成按chat_id新发。缺权限或不支持原话题回复时不发放发送引用。
- 发放和使用引用都检查主体有效性、原来源及出口的当前身份、原内容可用性、引用TTL及投递/领取状态。消息收发默认开放，不需要`message.reply`逐群grants；账号变化、主体或连接停用不允许旧引用继续发送。
- 修改映射影响后续冻结通知；已发放引用不改道，但发送前复核发现映射变化或迟到证据冲突时拒绝使用。unknown继续沿原幂等键核查，不换账号或新键重发。

## 验收边界

本批定向验证真实Core/SQLite与原生端口组合，不新增同事测试消息，不恢复轮询定时器，不宣称补齐个人全部私聊、Pin或未完事项唤醒。真实业务规则、身份映射与订阅由原接收对话自己设置；产品开发者只安装能力和授予准确目标权限。

## 回复引用与调用身份

已认证的 DJ 调用方可以使用有效回复引用。投递、出站及已领取收件按各自规则限制查看范围，并即时复核投影中的回复引用。可用引用随附 `reply_authority.recipient_principal_id` 和原绝对 `expires_at`，分别说明原通知接收方和截止时间。通知接收方及其授权计数不参与回复校验。

`message.reply_context(delivery_id)` 允许已认证调用方用准确的投递 ID 重取仍有效的回复引用。重取和使用都核对原消息、原生账号身份及来源和出口的接入范围，沿用原位置、领取代次和有效期。调用方变化时可继续使用已有有效引用。外发使用稳定的幂等键，先查询已有发送状态。

回复、引用续发、确认表情和实际出站共享回复记录校验。到期返回 `reply_context_expired`，引用、领取代次或身份失效返回 `stale_reference`，当前调用身份或连接访问受限返回 `forbidden`，正文不可用返回 `content_unavailable`。固定路由无法确认时返回 `reply_identity_unresolved`。已排队的回复遇到不可恢复的引用失效或内容销毁时记录确定未发送，停止出站重试。

## 引用、话题及表情回应

按[0015](0015-message-interactions.md)识别原生回应目标。有新提及时优先使用原生mentions；无新提及时可用已确认目标作者匹配同一reply_routes。目标作者不会加入mentions，表情原文里的其他提及不能改变出口。其余身份栅栏、歧义拒绝及原位置回复语义不变。

## 身份确定性修复施工（R1–R3）

目标：问本人由本人回复，问机器人由对应机器人回复；接收连接不等于被询问身份。
不修改任何对话规则正文、reply_routes、订阅或收件人退订资料。

- R1：`dispatch/evidence.eli` 在现有映射之外使用连接已登记的原生自身 ID；相同 Lark 原生 message_id、chat_id、source_time 的当前身份记录作为同一消息的证据。保留原生 mention.key；同一键或唯一提及可合并证据，绝不按昵称或不同应用 OpenID 字符串猜身份。显式提及优先于引用/话题；无提及的私聊按接收身份，引用/话题按已确认作者。缺证据返回 unmapped_target，矛盾返回 ambiguous_target，均不给发送引用；多对多输入仍保留。
- R2：冻结引用及发送提交前共享同一身份核验，迟到的另一连接也不能令既有引用用错身份。已冻结引用只校验自身身份快照、不改道；账号身份改变或权限失效拒绝，晚到线路副本不改写已经固定的身份。持久绑定及显式转移按[0031](0031-dispatch-contexts.md)。已有 accepted/unknown 不重发。自动 Working/Get 同样核验，清理已有表情继续允许。增加原生消息索引，使交叉核对按单消息有界读取，最多64份证据，超出拒绝。
- R3：同步 Skill，说明 ready 是机械确定的身份而非让 AI 选择；业务正文要 @ 谁仍由调用方按原事项决定，DJ不猜最初上报者。退订优先级完全不变。

验收：集中验证真实SQLite/Core下双连接到达顺序、跨应用单一/多提及、缺映射、冲突、迟到证据、引用刷新与出站提交切点、私聊及引用/话题优先级；再补关键纯函数保护。原生HTTP和AI端口使用明确替身，不向真实群发测试消息，不重放已撤回业务。

- 当前实现：`reply_route.basis`说明native_mentions/shared_native_message/private_recipient/native_interaction/source_default；unmapped_target与ambiguous_target无可发送引用。reply_identity_unresolved是不发送错误，不允许AI选择另一份重复通知的账号绕过。输入记录及订阅继续正常处理，跨连接证据核对不删除来源消息；同一目标的等价线路通知按[0031](0031-dispatch-contexts.md)归并，完整来源保持可查。

## 跨AI任务交接与外部工具补充

同一事项转交其他AI执行时，确定的IM发送身份必须随任务保留。默认执行者把内容原路交回协调者，由协调者通过DJ回复；不禁止执行者以自己的合法主体和有效回复引用直接调用DJ，也允许确有必要的Lark CLI补充。所有路径都必须保持同一确定账号及user/bot身份，不能按接收连接、CLI默认账号、群中旧消息作者或新的正文@对象自行更换。

派工与续接提供平台和租户、来源与出口连接、原生账号和身份计数、原消息和话题、协调者与执行者的原生会话 ID、约定返回方式、回复引用及有效期，以及已有发送记录。接手方用自己的 DJ 认证和准确的回复引用完成原路回复，可查原记录恢复缺失信息。交接不传凭据，固定原生路线和收件人退订继续生效。具体模板见[Skill任务交接](../../skills/dj/references/handoff.md)。

这是调用方的同身份约束；DJ机械校验经过自身的回复，不能拦截另一个程序直接调用Lark。原生CLI发送必须如实记录其message_id和身份，不伪造DJ台账。

## 私聊的接收视图与发送回显

同一原生私聊消息可能由接收账号和发送账号两条连接同时收取。无显式提及时，按每条连接已登记的原生自身身份及消息发送者区分接收视图与发送回显；存在接收视图时，仅接收视图参与回复账号选择，发送回显不构成第二个收件人。机器人收到本人私聊由机器人回复，反向机器人发给本人由本人回复；本人给自己的私聊在没有其他接收视图时仍沿本人身份处理。不根据显示名或跨应用OpenID猜测身份。

迟到回显不得使已固定的正确接收身份变成歧义；旧reply_context与重新取得的引用都使用同一选择逻辑，排队出站和自动表情也共享该校验。真实的多个接收身份冲突、身份更换、显式提及冲突仍保留原错误边界，不改订阅、规则、退订或消息可见性。

本次定向验收覆盖机器人私聊与本人回显的两种到达顺序、晚到回显后的旧引用与排队出站、反向机器人到本人私聊、本人自聊、其他人私聊及真正双接收冲突。复用话题层级、显式提及、权限变更、退订表情、早于回执的确认及队列切点回归。

## 话题作者与历史提及

当前消息的显式提及优先。无新提及时按直接引用作者、话题根作者、话题历史提及、仅历史参与依次选择。根消息由机器人发送且正文曾提及本人时，针对该根消息的后续回复仍先选机器人，不把旧提及与根作者并列。真正同层级冲突继续拒绝，所有回复引用与工作表情共享同一判定。
