# 0005 — 原生提及与确定性回复路径

## 职责

DJ根据平台原生提及及已保存的身份映射固定回复账号和原消息位置。AI可以看到被提及者和选定身份，但不选择回复账号、收件人或会话。AI只按自己维护的业务规则判断是否、何时调用`message.reply`并提交内容及受保护的`reply_context_id`。该操作不接受身份或目的地覆盖参数。

触发通知不等于新任务；多个通知可以归属同一任务，也可无需处理。AI普通输出、最终回答和任务完成均不自动转发IM，不能接管stdout或结束回调来冒充回复。真正外发仅由显式回复工具调用产生，允许在最终回答前执行。

## 数据和设置

平台原生`mentions`在接收、持久化、消息查询及push/pull信封中保留。`mentions.id`支持`eq`/`in`成员匹配：显式空列表不命中，缺失元数据为indeterminate；正文中的`@名字`不算提及。不按sender是否本人过滤，手工自发@本人或@bot同样处理。DJ已确认的外发回声去重与服务级黑名单继续有效。

接收AI自行通过`session.rules.update`维护本对话的`reply_routes`，并读回验证。每项只有`source_connection_id / mention_id / reply_connection_id`，最多32项；mention_id仅在指定源连接的当前身份版本内有效，不能跨应用复用OpenID。DJ保存源及出口的identity_revision。不同IM网络、明确冲突的租户或重复歧义映射拒绝，不增加跨账号自动故障切换。省略字段保留原设置，`[]`显式清空。该设置仅定义稳定身份映射，不把逐消息回复决策交给AI。

## 固定、校验与失败

- 冻结通知或领取时，DJ匹配原生mentions并选择对应出口；未命中已配置提及时保持原来源回复行为，适用于关键词等触发。
- 同一消息命中多个不同出口时公开`reply_route.status=ambiguous_target`，不生成可发送的reply_context、不自动双发、不让AI选择身份。匹配映射身份版本过期则为stale_reference，绝不回退其他账号。
- 单一出口生成的reply_context固定原chat/thread/message及出口connection和identity_revision；另存原来源地址及版本。出口只能是同平台、品牌且无明确租户冲突的获准连接，跨连接当前仅支持Lark。缺失租户标识不作为同租户证明；真正发送固定使用原生message_id的回复接口，由平台复核该出口访问原消息的权限，绝不改成按chat_id新发。缺权限或不支持原话题回复时不发放发送引用。
- 发放和使用引用都检查主体有效性、原来源及出口的当前身份、原内容可用性、引用TTL及投递/领取状态。消息收发默认开放，不需要`message.reply`逐群grants；账号变化、主体或连接停用不允许旧引用继续发送。
- 修改映射影响后续冻结通知；已发放引用保持原路径直到失效，不能被修改规则偷偷改道。unknown继续沿原幂等键核查，不换账号或新键重发。

## 验收边界

本批定向验证真实Core/SQLite与原生端口组合，不新增同事测试消息，不恢复轮询定时器，不宣称补齐个人全部私聊、Pin或未完事项唤醒。真实业务规则、身份映射与订阅由原接收对话自己设置；产品开发者只安装能力和授予准确目标权限。

## 权限变更后的回复引用

message.reply_context(delivery_id) 允许原接收者在原持久回复记录仍有效时重新取得当前授权下的引用。重新执行原消息可见性、原账号身份栅栏及源/目的 message.reply 校验；不更改已冻结回复位置，不延长原有效期，不为其他主体取得引用，不重放原业务。旧引用继续失效。外发仍用原逻辑幂等键，已 accepted 不重发。
