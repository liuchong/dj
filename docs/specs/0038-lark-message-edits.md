# 0038 — Lark 消息编辑与新增提及

Lark 消息详情提供 `updated`、`update_time` 和真实 `mentions`。DJ 通过 WebSocket `im.message.updated_v1`（按 `message_id` 回读权威消息详情）与官方批量消息定时回读双通道检查编辑，覆盖本人及机器人连接。WebSocket 与原普通收件仍负责新消息。

## 收取

- 实时路径：`im.message.updated_v1` 到达后，按同连接同身份已收原消息通过 `mget` 拉取最新快照，不受巡检时间窗与激活时间限制，仍以原消息一致性和推进的 `update_time` 去重。
- 兜底轮询：每条连接独立检查已入库的近 2 小时（`7200s`）文本和富文本消息，每轮先查最新消息，每批最多 20 条，按持久游标和连接的读取预算继续翻页。一次扫描结束后按 15 秒节奏开启下一轮。限流沿用原生退避；个别消息导致整批拒绝时逐条定位并继续其他消息。编辑检查失败单独在 `connection.probe.event_source.poll_fallback.edit_poll` 显示。
- 只接受原生消息 ID、群或私聊、作者、原始发送时间与本地记录一致且原生更新时间确实推进的编辑。轮询只回扫编辑扫描启用后发出的原消息（实时 `im.message.updated_v1` 无此启用时间限制），避免轮询把启用前已存在的历史提及误认为新加。旧身份的消息不参与扫描。缺少授权或未找到本地原消息、或两次回读之间被覆盖的中间编辑无法从此机制取得。
- 原消息记录保留。新事件类型为 `message.edited`，沿原消息 ID、群、引用和话题保存更新后的正文；事件时间是原生更新时间。去重使用原生消息和更新时间，两条连接看到同一次编辑时复用共享通知键，包括一条连接首次通过 HTTP 看到的已经是该编辑内容。本地历史和引用显示最新可读正文，原事件仍可单独查询。重启继续原检查游标，已读到的编辑不会被视为新消息。

## 触发与回复

- 编辑事件 `mentions` 表示相对于上一次确认状态新增的真实提及；重复编辑正文、改显示名或删除 @ 不构成新的提及。两次分别观察到移除和重新加入，才认定为再次添加。新建默认订阅会识别编辑后新增的对当前身份的 @。已有指定 `event_kinds` 的订阅需显式加入 `message.edited`，并在原 @ 谓词允许此事件类型。
- 编辑触发继续走同一套触发黑名单、订阅、双连接去重和原会话投递。被拦时仍保存编辑。只有获准匹配后才可能点处理中表情。纯编辑本身不重执行管理命令或推断该取消 AI 工作。
- `@所有人`（飞书 `text` 中的 `@_all`、`post` 中的 `tag="at", user_id="all"` 或 `mentions[].id="all"`）统一解析为 `mentions_all: true`（新建与编辑均以当前消息为准，不与旧版本做差分，且不进入个人 `mentions`）；订阅通过 `mention_all_policy`（`enabled` 默认 `true`、`allow_chat_ids`、`deny_chat_ids`，优先级 `deny_chat_ids > allow_chat_ids > enabled`）控制群全员触发范围。经由编辑（含首见即已编辑快照）触发 `@所有人` 且未携带个人 `@` 或交互绑定时仍保留 `source_default` 回复出口；若同一 `@所有人` 快照同时存在机器人与个人视图且无更具体的个人 `@` 或已有绑定，则优先选定唯一机器人连接作为默认回复出口，以正常签发 `reply_context_id` 与处理中表情。
- 通知列出 `message_edit`，新增提及另列 `edit_mention`。回复引用仍定位同一原生消息与话题，回复身份按当次编辑的完整原生提及和原交互证据解析，新增提及只用于触发。无法确认唯一出口时保留通知及来源证据；若首到视图暂未解析出唯一出口导致首次通知 `reply_context_id` 为空，后续对端同快照视图到达并确立唯一出口后，在原投递回复有效期内调用 `message.reply_context` 可按同一证据链补发回复引用并绑定交互身份。既有身份绑定不依靠收到副本的先后改写。
