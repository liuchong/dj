# 0028 — 组订阅与单成员分发

状态：业务实现及定向集成、保护性测试已完成；采用范围见文末。调查/实现日期：2026-11-16。

## 目标与边界

普通订阅继续按 [0027](0027-many-to-many-subscribers.md) 多对多通知。新增显式组订阅：多个已登记原生对话共同成为候选，每个匹配事件在该订阅中选择一个成员接收。其他普通订阅、其他组订阅仍各自独立匹配，同一事件可以通过不同订阅到达不同对话。

这是调用方指定成员、条件和算法后的机械分发，不判断任务负责人、能力强弱、任务是否相同或成员之间如何协作。不把事件分配自动扩展为后续整段话题绑定；话题连续处理由 AI 自己使用上下文和显式工具决定。不启动替代 Agent、不自动改模型、不购买或启用额外额度。

单成员约束针对一条组订阅的一次事件分发，不宣称整个系统端到端 exactly-once，也不保证只执行一次业务。成员通过另一条独立订阅接收相同事件不违反组内分发约束。

## 组、成员和订阅

组只拥有成员集合；订阅拥有来源、过滤、提示词、上下文、TTL 和本条分发策略。不要为每个成员复制一份订阅并各自抢跑；组自身不新增 IM 连接，不改变来源账号或回复身份。

- `subscription_groups`：`group_id`、管理主体、名称、成员集合和状态。名称只用于展示，不能作为寻址键。
- 成员使用已有 `agent_id`，保留准确工具、实例、命名空间和原生会话身份。成员属性为 `enabled`、整数 `priority`；相同 Agent 不重复加入，同一真实目标不通过别名增加选中概率。
- 订阅规范在 `agent_id` 与 `group_id` 中恰好指定一个。省略组目标时仍为现有普通订阅；不改变现有字段含义。
- `distribution` 为组订阅可选参数，包含 `algorithm` 和 `eligibility`。创建、更新时可在请求中选择，影响该次订阅提交后的有效策略，不给每条消息另造自然语言算法入口。
- 提供 `subscription.group.create/get/list/update/delete`；成员整体更新使用已有操作幂等与并发校验机制。组有在用订阅时删除返回明确冲突，不静默删除订阅。`subscription.group.dispatches` 按订阅读取实际选择、状态、排除原因及最多64条选择历史，after_id/limit续扫。
- 继续使用 `subscription.preview/create/update/pause/resume/delete` 管理组订阅。预览返回成员、有效算法、排除原因、额度观测时间与未知项，不消耗轮询游标、不预占消息。

组管理和成员使用分别校验。创建/更新时确认调用方可以管理该组并使用每个准确 Agent；订阅管理权不代表能控制任意其他 Agent。来源可见性对候选成员各自的 recipient 主体独立核验，不取权限并集，不借组绕过权限。发送前重验组/订阅状态、成员仍在组内、当前权限及原生身份。

成员和策略更新只影响尚未开始原生提交的分发及后续事件；已经受理或结果不确定的分发保留原选择。暂停、退订、删除、成员移除不能通过重新选人重发已受理消息。已选但尚未提交的记录按同一事务作废或重选，保持可审计原因。

## 配置与组合

服务配置及订阅请求示例：

```json
{
  "group_distribution": {
    "algorithm": "round_robin",
    "eligibility": { "quota": "exclude_exhausted" }
  }
}
```

```json
{
  "group_id": "group_example",
  "distribution": {
    "algorithm": "priority",
    "eligibility": { "quota": "require_available" }
  }
}
```

请求显式字段覆盖服务同名默认字段；未指定字段继承服务默认。内建默认是 `round_robin` + `exclude_exhausted`。有效策略在订阅提交时固化并公开读回；服务默认变化不悄悄改变已有订阅。请求修改仍走现有订阅预览/提交，不新增兼容入口或内部产品版本。

筛选和排序分离：

1. 按订阅过滤匹配事件；按有效权限、登记状态、原生可投递状态和所选额度策略筛选成员。
2. 对剩余成员应用一种选择算法。未来可添加独立筛选器或排序器，不把厂商额度 RPC、IM 条件和 SQL 写入塞进算法函数。
3. 持久登记选择，再沿原 delivery/attempt/binding/submitting 链路发送。

| 算法 | 行为 |
| --- | --- |
| `random` | 在当前合格成员中等概率选择；使用宿主随机端口，选择结果落盘，恢复不重新抽签 |
| `round_robin` | 成员按稳定 `agent_id` 排序，从该订阅上次选中成员之后循环查找；跳过不合格成员，游标与选择同事务提交，重启保留公平位置 |
| `priority` | 数字较小者优先；同优先级按稳定 `agent_id` 决胜。允许高优先级持续接收，不承诺低优先级不饥饿 |

“是否有额度”首先作为以上所有算法都可组合的资格条件，不另造一套随机/轮询实现。不跨不同供应商直接比较百分比来决定“谁额度最多”：窗口、模型组、单位和超额付费设置可能不可比。将来增加额度排序时须明确同一可比较范围及缺失值策略。

## 额度观测

统一观测为 `available / exhausted / unknown`，附 `observed_at`、`valid_until`、`reset_at`、`source`、证据类型和脱敏原因。`available` 只表示观测时允许该账户/模型继续使用，不保证足够完成本条任务。

观测归属必须绑定准确实例、账户/凭据身份和模型/配额桶，不只按工具名或会话 ID 缓存。相同账户的多个对话可以共享一项已证实的额度观测，但不能将多个模型行的百分比相加。账户或模型切换、实例代次变化、观测过期后重新核对适用性。

| `eligibility.quota` | 已知可用 | 已知耗尽 | 未知/过期/查询失败 |
| --- | --- | --- | --- |
| `ignore` | 可参与 | 可参与 | 可参与 |
| `exclude_exhausted`（默认） | 可参与 | 排除 | 可参与，并公开未知 |
| `require_available` | 可参与 | 排除 | 暂不参与，保留待投 |

基线额度为零但平台已经允许超额用量，不直接判为 `exhausted`；必须考虑相同账户的实际准入结果。重置时间到达只说明应刷新观测，不能凭时钟自行宣称有额度。

优先复用已有实例的原生更新或只读查询。对同一额度范围合并并发刷新，使用有界缓存和退避；无原生推送时按需刷新，不为每条消息/每个成员重复查询。默认有效期上限 60 秒、单次查询截止 2 秒，原生过期信息可以缩短有效期；查询失败转未知，不把故障当作零额度。不新启 Agent CLI 或 App Server 来冒充目标实例，不靠给模型发送 `/usage` 或探测提示词获取额度。

## 本轮调查证据与限制

DJ现提供统一 `agent.availability` 观测及适配器可选 `availability` 端口；OpenCode 的原生提示词受理和 Antigravity 的输入确认可以先于模型执行，不能据 `accepted` 推断额度充足。

| 工具/入口 | 已核内容 | 接入结论 |
| --- | --- | --- |
| Codex App Server | 官方文档明确有 `account/rateLimits/read`、`account/rateLimits/updated`、分桶及重置字段 | 协议可提供额度；DJ 当前 Desktop owner IPC 不等于该接口。只有绑定到目标实际账户/已有实例的接口才可用，不能拿另一个 CLI 账户代替 |
| Antigravity Desktop | 本轮通过现有本机语言服务的只读 `GetUserStatus` 实际读到逐模型 `remainingFraction` 对应余量与 `resetTime` | 已接入DJ原生额度适配；该私有协议对客户端版本敏感，读取失败应为未知。官方套餐文档也区分基线额度与可选超额额度 |
| OpenCode | 当前 DJ 使用现有服务 `/api/session/.../prompt`；受理阶段的 HTTP 429 只保留 `retryable`，没有配额桶/耗尽分类 | 已补原生结构化错误分类，用于后续分发资格；未核得当前服务的跨 provider 通用剩余额度 API。各 provider 需要分别核对，不把会话 token/cost 当余额。官方 `docs/server` 当前跳转到 V1，不能用其旧路径宣称 V2 已支持 |
| Cursor | 官方 Admin API 描述团队用量及支出；DJ 当前 Desktop Bridge 没有个人实时余额返回 | 暂按未知；组织累计消费不能直接替代准确个人/模型实时可用性 |
| Claude Code | 官方消息协议区分 `billing_error`、`rate_limit`、`overloaded` 等错误 | 可作为后续原生错误分类依据；是否在已有接收端可观测需另核，不因文档存在就声明 DJ 已接入 |
| Pi、Kimi、DSH及其他端口 | 本轮未逐一验证目标实例的账户额度接口 | 维持未知；不阻塞通用组分发实现，也不虚报全工具覆盖 |

官方参考：[Codex App Server](https://developers.openai.com/codex/app-server/)、[Antigravity 套餐与超额额度](https://antigravity.google/docs/plans)、[OpenCode 当前入口](https://opencode.ai/docs/)、[Cursor Admin API](https://cursor.com/docs/account/teams/admin-api)、[Claude 消息与错误类型](https://code.claude.com/docs/en/agent-sdk/typescript)。文档能力、本机只读验证、DJ 已接入能力分别记录。本轮没有发送试探消息、触发模型执行或更改真实订阅。

## 错误、换成员与恢复

- 统一分类为 `quota_exhausted`、`rate_limited`、`overloaded`、`authentication_failed`、`offline`、`unknown`；保留原生稳定码、适用范围和 `retry_after`。429 本身不能确定账户没额度；403 也不能单独作为欠费证明。不对任意聊天文本做关键词匹配后封禁成员。
- 原生明确返回额度/准入拒绝并证明 `definite_not_sent=true`，或提交前已经发现成员不合格，可以撤销本次选择并按同一策略选择另一个成员。每轮最多检查 32 个成员，不重复试同一失效观测；原生调用沿全局并发和时间预算，不能一次阻塞整个收件调度。
- 已原生 `accepted`：本次组分发已经结束。随后模型额度耗尽可以更新该成员之后的额度观测，但不自动把本条再交给别人。需要业务转交时由 AI/用户显式选择。
- 已 `submitting/unknown`：保留原成员及原 attempt 核实，不能因没有看到回复、超时或 Working 消失就改投另一成员。正向核实仍按 [0018](0018-offline-recovery.md)。
- 无合格成员：持久 `waiting_member`，公开原因与下次复核时间，随相关成员/额度变化或有界定时复核恢复，遵守本订阅 TTL 和全局容量；不是丢弃或广播兜底。
- 在 SQLite 事务内登记唯一 `(subscription_id,event_id)` 的组分发记录、选中成员与轮询游标，然后创建或复用原目标投递。记录所用订阅状态、成员集合摘要、有效算法和排除原因；重启、重复匹配、并发调度均复用同一结果。
- 组订阅以自身 subscription_id 作为投递归并边界，普通订阅继续按原 route/event 归并。这样普通订阅已受理后，较晚恢复的组订阅仍会得到带自身提示词的完整通知，不能把普通投递的回执冒充组投递。不同组和普通订阅可独立送达同一目标；撤销本组选择不影响其他订阅，也不改写冻结的 attempt。
- 组内选择不改变消息来源、确定回复身份、上下文、出站退订或 Working 清理。未被选中者不获得通知/回复引用，已选中者仍使用现有授权和 Skill 能力。

## 模块划分与施工范围

当前文件/模块：

| 位置 | 职责 |
| --- | --- |
| `src/subscriptions/groups.eli` | 组与成员 CRUD、授权和订阅目标校验 |
| `src/routing/group-selection.eli` | 纯资格筛选与算法选择；输入已规范化事实，输出选择及原因，无网络/SQL |
| `src/delivery/group-dispatch.eli` | 持久选择、游标、待成员恢复、与现有 contribution/delivery 链路衔接 |
| `src/registry/availability.eli` | 额度观测规范化、范围校验、缓存/到期与原生错误归类 |
| `src/adapters/agent/*` | 各工具实际原生额度/错误接口；没有能力明确 unsupported |

`matcher` 只在事件真实匹配后交给组分发，不把组当成多个独立成员订阅；`service/runtime` 只调度有界恢复，不内嵌选人算法。公共操作目录、验证 schema、SQLite schema/repository、配置默认、固定接线、通知元数据与 subscriber_hints 一次接通；提示只列实际获选接收者，不把未选成员写成“已收到”。

组订阅的 `pull` 也必须先选择单个成员，再生成带选中 Agent 身份的 inbox entry/租约；其他成员不能凭共享 principal 抢走另一成员已分配的记录。不能只在 push 路径实现单成员语义。

## 本批验证范围

新增4项Core/SQLite集成和3项关键保护性单测，复用普通多订阅、固定接线与原生忙时输入的定向回归。使用本地协议替身与真实SQLite，不向真实IM发测试消息，不创建真实组或改变现有订阅。不同工具的额度覆盖分别记录，未知额度不冒充可查。组订阅以自身subscription_id作为投递归并边界，避免普通订阅先受理后漏掉本组提示词。
