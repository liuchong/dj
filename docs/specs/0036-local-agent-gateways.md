# 0036 本机 OpenClaw 与 Hermes 接线

DJ 可以通过正在运行的 OpenClaw Gateway 和 Hermes 后台服务发现对话、创建和改名、投递文本、读取历史。调用方使用已有 `agent.discover`、`session.*`、`delivery.get` 与目录接口。

## 运行结构

- 配置 `agent_endpoints`，一条记录对应一个已运行的本机端点。端点只接受数字回环地址及显式端口。鉴权材料从用户私有文件读取。
- 每端点持有一个有界 WebSocket。原生进程的启动标识用于重验实例 epoch。发现、写入、历史查询和具有效果的回执继续走 DJ 现有组件。
- OpenClaw 在每次写操作前读取原生会话键与会话 ID。消息提交携带二者及一个原生幂等键，通过 `deliver: false` 留在对话。历史读回核对同一原生会话 ID。
- Hermes 以数据库中的原生会话 ID 定位对话。发送时经 `session.resume` 取得运行句柄，校验读回的原生 ID 后使用该句柄。REST 只查询目录与历史。工作中投递使用 Hermes 既有后续输入队列。
- 原生接受只证明收到输入。发生断线或超时且已发出请求时记录 `unknown`，调用方可读回同一对话核实。启动、停止、通知订阅和回复都使用各自的既有接口和授权。

## 验收

同一个 DJ 实例分别通过两个原生接口对隔离的测试对话完成发现、创建、改名、输入受理与历史读回。验证模型回复时使用独立文本标记，实机环境不经过 IM。
