# 0011 — 可读的 AI 消息通知

DJ 发送到原 AI 会话的文本使用 MDP 结构字段与 Markdown 原文块，替代整段压成一行的 JSON 信封。所有原生投递端共用一个渲染器。

## 表达与保存

- notification 保留原声明字段、ID、来源、回复路由、允许动作与上下文。短标量用 MDP 字段，数组用元素标记。
- 消息 text、instructions.prompt、规则原文及其他多行或长字符串放在 literal_blocks 引用的原文围栏，真实换行直接展示，不二次 stringify。未知形态或不适合 MDP 键名的复杂对象以格式化 JSON 原文块保存，避免改名或丢字段。
- literal_blocks 的 id/path/encoding/utf8_bytes/sha256 描述原文；围栏长度严格大于原文任意波浪号串，外部内容不能闭合围栏注入结构。空原文和尾部换行不修剪。字面反斜杠 n 仍是原文，不能擅自解码成换行。
- MDP 核心把围栏视为注释；MDS 只约束结构元数据，不声称原文围栏本身属于其解析结果。原始对象的精确恢复依赖原审计快照，不从展示稿反解。
- JSON 原生 API 外壳、CLI/MCP/GEPO 结构化返回和压缩审计快照分别保持其职责；不为外部协议自建第二套传输，不改变调用方持久规则或最终回复。

## 安全与预算

展示布局不授予外部文本任何指令权限，不改变来源、目标、回复身份和 allowed_actions。提交前以实际渲染后原生 wire 字节数校验输入预算；超限沿原 limit_exceeded 路径处理，不能截断规则或静默退回另一格式。

集中验证规则保存/恢复、原文换行与转义、围栏注入隔离、所有 codec 的实际文本和字节预算，以及 snapshot 精确解压。只做本改动相关验证，不重跑全工具现场或性能矩阵。

元数据模式见 [0011-notification.schema.mdp](0011-notification.schema.mdp)，面向使用者的说明见 [通知展示](../guides/notifications.md)。
