# 验收设计

当前执行仅围绕 Codex、Cursor 主要业务交付做必要验证，其他工具专项验收在交付后安排；不逐工具执行下方完整矩阵。旧场景保留，已通过证据复用，未执行不标通过。当前范围见[发布范围](release-scope.md)。

本文件保留完整行为场景与验收定义，不作为当前运行结果。生产实现及本地验证已推进至S3，准确进度、失败和真实资源缺口见[当前状态](status.md)与唯一[TODO](../TODO.md)；下表不自动转为运行通过。真实控制器与资源的装配前置见[真实验收准备](construction/real-preflight.md)。层次按被测边界判定，快慢标签只决定调度，不改变测试性质。

## 测试组织

单元覆盖规则、状态、标识、参数和错误映射；集成验证真实事务、协议帧、重连与内部接线；系统验证完整 DJ 服务行为。真实端到端以 IM 发出消息为起点、指定 Agent 原会话工作并回复原话题为终点。替身协议可证明 DJ 逻辑，不能替代厂商实际唤醒。

每适配器至少独立验证 idle、busy、offline、权限、版本不符、重复/unknown、回复和上下文身份。桌面与 CLI、existing 与 managed、OS 与版本分别记录，不靠一个工具的成功推定全部。UI 渲染若声称同步则需要真实渲染证据；普通服务路由不额外要求 UI。
