# 验收说明

验证围绕当前变更及已授权范围进行，不把全部工具、IM、模型、可选能力或性能矩阵自动设为每次交付的前置。已通过且未受影响的证据复用；新失败保留原记录，修复后仅复验受影响内容。

执行顺序为当前功能阶段全部业务实现 → 必要集成功能验收 → 关键保护性测试。当前事实见[状态](status.md)，待完成工作见[待办](../TODO.md)，可执行用例和启用状态以 `tests/cases.json` 为准。历史编号与场景追溯见[原场景矩阵](archive/acceptance-matrix.md)，不据此恢复已排除的运行方式。

## 测试层次

- 单元：规则、状态转换、标识、参数与错误映射，保护关键边界和已修缺陷。
- 集成：真实事务、接口接线、协议帧、重连、授权、回滚和幂等；替身协议只能证明 DJ 逻辑。
- 系统：完整 DJ 服务、启动停止、持久恢复与目录包行为。
- 真实端到端：准确 IM 账号和原消息 → 指定 Agent 原会话 → 显式回复原位置。输入接受、模型额度错误与业务完成分别记录。

真实消息验证必须使用当前授权的账号、来源与目标，不能用重放、轮询或新建 Agent CLI 冒充实时接线。客户端或工具的成功不外推到其他产品、版本与运行形态。没有实际受影响的变更时，不重跑已通过的全套用例。

## 证据与执行边界

记录 setup/test/teardown、逐例耗时、环境、输入/产物身份、失败和清理结果。慢测试、真实模型及性能组单独调度；默认测试不隐式启动它们。资源、会话与端口隔离，故障注入需证明命中实际持久点。

保留必要的原生读回；实现、配置安装、协议接受、模型响应与任务完成分别说明。真实凭据、消息和会话身份只存私有证据，不提交到仓库。文件链接与排版检查不能冒充业务验证，文档维护不需要触发新消息或重跑全套。
