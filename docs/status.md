## 近期维护

- 服务通过独立Rack包装配公共能力，配置、消息状态和操作台账仍由DJ管理。
- 收件人禁收由服务自动识别并持久保存，启动恢复漏登命令；不依赖AI任务备注。`force_send`只豁免单条文字，已完成47项定向集成/保护性检查、487条断言，不代表对真实收件人做过强制发送测试。
- 回复身份按原生提及及同一消息的跨连接证据核验，缺映射或冲突明确拒绝；不把双连接身份选择交给AI。
- Lark合并转发详情只选取所请求的原消息，避免补收因返回子消息而停滞；离线补收、表情覆盖和当前连接健康仍须分别核对。

## 开放边界

- Lark 本人可见范围、文档提及及表格事件，按原生事件类型、权限和实际新事件逐项确认；读取、重放或平台订阅受理不能冒充实时触发。
- Slack已实现并完成本地协议/集成验证，真实Slack账号收发仍需凭据与现场验证；不从Lark接线结果外推。其他 IM、实际客户端 MCP/Hook 启用以及可选创建/启停仍按各自证据说明，不作为反复重跑全矩阵的理由。
- `T27.route-load.performance` 的完整吞吐目标尚未取得通过证据，不声明达到 `100 events/s`。
- DJ 接受输入或 IM 平台接受回复，不等于 Agent 已完成任务或人已阅读。
