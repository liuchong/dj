# 组件边界与确定性运行

## 产品硬边界

DJ 是网关、中转站和订阅转发小服务，没有 AI 能力，也不内置 Agent 执行循环。DJ 不调用模型 API，不配置用于推理的模型或 token 预算，不依靠大模型、embedding、向量检索、语义分类、自动摘要、翻译或 OCR 来决定路由、判断身份、恢复投递或生成答案。

目标 Agent 本身可以使用大模型；DJ 向其已登记收件口提交外部消息，是转发行为。模型调用、工作规划、工具执行与业务结果属于该外部工具/调用方，不进入 DJ 的路由核心。DJ 不代持自身推理所需的模型密钥；厂商工具的既有认证仍由相应运行时管理。

这一约束适用于插件、嵌入模式、错误处理和未来扩展。不能在“规则不确定”“目标同名”或“消息太长”时加入一次模型调用。外部 Agent 可以理解自然语言并通过相同受校验接口提交规则或新消息；那是独立调用者，不是 DJ 隐藏的智能模块。

统一会话目录、机械搜索、免订阅直发与显式启动/创建也属于消息组件范围，见 [Agent 控制面](agent-control-plane.md)。DJ 可以按获准 profile 启动外部工具、按原生协议建空会话，但不能自己制定工作计划或根据搜索结果选“最合适”的会话。查询不启动工具，发送不偷偷创建/恢复，创建不自动 prompt。首期只有 CLI/MCP/API，没有 IM 管理命令或图形操作界面。

## 人、调用方模型与服务的责任

| 工作 | 责任方 | DJ 能做的确定性检查 |
| --- | --- | --- |
| 解释用户想订阅什么、选哪个会话 | 人或调用方模型 | 参数类型、枚举、句柄类型、范围、有效期与权限 |
| 从候选中选择目标、解释同名歧义 | 人或调用方模型 | 原生身份、绑定约束、完整分页、不可变目标键 |
| 把“重要消息”等描述变成可执行规则 | 调用方模型与用户 | 仅接受明确定义的结构化谓词；含义未定则拒绝猜测 |
| 接收事件、匹配、排队、转发、回复定位 | DJ | 规则版本、订阅贡献、队列、路由引用与回执 |
| 阅读消息、决定做什么、形成回复 | 外部 Agent | 保持 external_message 来源，限制出站目的地 |
| 判定投递是否接受/开始/结束 | 厂商协议观察，DJ 映射 | 只按明确字段和事件转换；自报单独标记 |

格式正确但违背用户意图的选择，DJ 无法理解。优化目标是让调用方少猜参数、少复制 ID，并让错误可被定位和修正；不能承诺模型永不犯错。Skill 提供用法，运行时仍独立执行校验，不能把正确性全部寄托于模型读懂说明。

## 热路径与成本

热路径固定为：验证来源 → 规范化 → 持久入库 → 按连接/对话/话题/事件类型取订阅候选 → 执行编译后的有界谓词 → 持久排队 → 检查目标/授权/订阅贡献 → 提交外部输入 → 记录观察。

规则在 preview 时规范化和校验，创建/更新时建立不可变编译版本与索引。不得每条消息全表扫描所有订阅、重复解析规则、调用模型或读取全量 Agent 历史。否定谓词也必须受正向 sources 和 event_kinds 范围约束，不能形成全租户广播扫描。

事件正文规范化一次；相同的字面匹配条件在同一事件中复用结果。候选与决定按固定页处理，以 ingress_seq 为快照，不通过 wall-clock 猜规则版本。容量不足或一次预算耗尽时记录可恢复 routing work 并让出工作线程，不静默忽略剩余候选，也不把未计算当作不匹配。

- 每订阅的深度、叶子、来源和正文预算见领域模型；超限在接入前拒绝。
- 每轮匹配最多处理 128 个候选、累计最多 1000 万次正文字符访问；未处理部分持久保存游标，下一轮继续。该值为首轮调度默认，可配置且需测量。
- 相同物理连接只接收一份事件流；目标状态观察尽量使用原生事件，缺事件时由服务退避探测，不能依赖 Agent 自己定时拉取。
- 目标之间按轮转配额公平调度；一个 unknown、慢连接或大量订阅的目标不能阻塞其他目标。来源接入、规则匹配和外部写出使用独立有界队列。
- 控制面查询/预览有独立并发与大小预算，不让全量 discover 或 history search 占住转发工作线程。默认本地存储与本地消息查询，不引入必需的云服务。

## 性能验收目标

以下是待测目标，不是已实现指标，也不以此预选语言：参考环境至少 8 个逻辑 CPU、16 GiB 内存；100 个连接配置、10000 个订阅、1000 个目标；持续 100 条事件/秒，每条正文 4 KiB、命中候选不超过 64 个。

路由候选获取与规则计算 CPU 时间 p95 目标不超过 10 ms；从 DJ 入库到 ready 的排队延迟单独记录。报告 p50/p95/p99、吞吐、积压、数据库写入、重连和进程占用；外部模型响应耗时不计入 DJ 路由计算，但端到端结果另报。DJ 与自有适配进程的稳定内存目标 256 MiB，外部 Agent 进程单列并报告合计，不能把总占用藏掉。

超过基准的扇出/正文/突发走压力与背压场景，不保证仍有同一延迟。磁盘满、源 ACK 无法控制、源重放丢失等情况按既定保证边界公开。实际指标和调度参数在实现与测量后校准，本轮不运行基准或产品测试。

首期具体宿主与同步存储成本见 [技术选型](technical-stack.md)，平台裁剪见 [首批范围](release-scope.md)。组件目标不因所选语言而改变，尚未测得的性能不能由语言或宿主的宣传数字替代。
