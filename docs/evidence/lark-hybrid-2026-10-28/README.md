# Lark 双通道收件落地验证：2026-10-28

本记录承接[先前收件矩阵](../lark-receive-2026-10-28/README.md)，记录共享 WebSocket＋HTTP 收件器部署后的结果。名称、账号、群及消息 ID 使用代号，未保存真实消息正文或凭据。

## 已交付行为

- user／bot 共用 `createLarkInboxPoller`，连接各自持有独立凭据、限流器、错误和断点。
- 保留现有 WebSocket；HTTP 默认 2 秒，可用 `inbox_poll_seconds` 配置 1–300 秒。
- 本人按官方全局消息查询补齐群聊与私聊，机器人按可发现群与已知私聊补齐。
- 两种来源共用 `im_event_inbox` 与已有 Core：同连接、同原生消息的创建事件只入库一次，之后沿原订阅、触发过滤和回复路由处理。`events` 保存历史，沿用既有保留期限。
- 消息审计区分 `receive_transport=websocket/poll`；探针分别报告连接状态、HTTP 覆盖及错误。轮询不冒充即时推送。

### 常驻服务真实新消息

北京时间约 **21:33**，机器人 A／B 分别发送私聊和群里 @本人的新消息，再由 B 在测试群 @A 作实时阳性对照。均通过官方 API 产生真实新消息，无手动恢复、历史重放或诊断程序代投。

| 新消息 | 机器人连接 A | 本人连接 B |
| --- | --- | --- |
| A → 本人私聊 | HTTP 入库；不触发本连接订阅 | HTTP 入库并投递原接收者 |
| B → 本人私聊 | 不属于本连接可读会话 | HTTP 入库并投递原接收者 |
| A → 群里 @本人 | HTTP 入库；按既有规则投递 | HTTP 入库；按既有规则投递 |
| B → 群里 @本人 | HTTP 入库；按既有规则投递 | HTTP 入库；按既有规则投递 |
| B → 群里 @A | WebSocket 入库并投递 | HTTP 保存历史；本连接规则不命中 |

合计 **8 条 HTTP、1 条 WebSocket 创建事件**，每个连接／原生消息键恰好一条。7 条原生投递获 `accepted`；原接收对话实际重读已安装 Skill，并通过 DJ 对这 7 条通信测试执行 `delivery.complete(no_reply)`。七条处理项均为 completed，Typing 清理均为 done。

同一物理消息出现在两个账号连接时，各自保留身份和历史。已有订阅若同时命中两条来源，仍分别投递；本次去重不跨账号合并授权，也未擅改接收对话的订阅规则。

来源标记最终收紧为仅由真正的 WebSocket 回调写入，通用归一化／手动读取不默认标成实时；对应保护断言通过。最终安装后再次发送一条机器人私聊和一条机器人互 @，得到两条 HTTP 与一条 WebSocket 入库，三个连接／消息键均只有一条创建事件。

逐条脱敏记录、源文件摘要与构建摘要见 [results.json](results.json)。两条常驻连接均报告 WebSocket connected、HTTP ready、间隔 2 秒。已有数据库、账号授权及回复路由保留。

## 证据边界

- 2 秒是查询窗口的目标周期，不保证官方索引零延迟或固定到达时限。
- 机器人只能补读官方可发现的群和已知私聊，不能声称发现了全部未知私聊。
- 本记录证明这些真实样本从平台进入 DJ、历史和原接收对话；不证明模型完成了额外业务任务。
- 对照采集仍可继续。编译与采集程序交接期间，服务 WebSocket 保持原运行；采集程序保留原始开始时间及事件游标，HTTP 从旧水位重叠续查。该时段的 HTTP 首次观察延迟不能用来评价服务轮询速度。

## 固化的完整链路集成测试

`T41.hybrid-inbox-flow.integration` 位于 `tests/integration/hybrid-inbox.test.eli`，通过正式 `createLarkEventPort` 装配两个连接；仅平台 WebSocket／HTTP 与 Agent 接收端使用可控替身，其余使用实际 Core、SQLite、订阅、过滤、投递和 Working 生命周期。测试不直接调用 `Core.ingest`，不读取本机凭据、不外发真实消息。

覆盖本人收机器人私聊、机器人收人类私聊、群聊提及两种身份、未提及消息、黑名单消息，以及 WebSocket 先到和 HTTP 先到的重叠。断言同连接不重复、不同连接保留独立来源、完整换行／thread／引用入库、仅四条匹配投递、按本人身份原路回复，以及回复／无需回复后全部 Typing 撤销。已有 `T41.hybrid-inbox.integration` 继续覆盖分页、持久断点和错误隔离。
